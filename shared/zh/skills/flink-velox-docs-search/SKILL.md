# flink-velox-docs-search

## 用途

不灌爆上下文窗口地回答“X在哪有文档/在哪实现”：先搜已安装docs与本地工作区，本地回答不了才落到官方在线文档。

## 输入：范围限定

调用方在输入侧声明搜索范围，本技能不自行扩围：

- 默认范围=调用方Agent绑定的docs单元（Agent frontmatter的`docs:`清单），对应目标项目`docs/gfvbot/`下已安装的目录。
- 显式传入目录清单时只搜清单内的单元；要跨出绑定范围必须由调用方明说。

## 本地资源，按尝试顺序

1. 目标项目`docs/gfvbot/`下已安装的docs单元——GFV沉淀的架构、表达式卡片、internals剖析、验证手册，是第一落点，在限定范围内grep。
2. `<workspace>/repos/`下的源码——终极事实来源。仓库-职责映射与分支基线见`references/module-map.md`。
3. 目标项目自己的文档树——设计笔记、特性调研、troubleshooting记录都在那里，回答项目特有问题常比上游文档快。
4. velox仓内渲染的Velox上游文档（开发者指南、算子、表达式、函数参考）——上网之前先在仓内grep。

## 相关度评估

命中先评估再上报，只挑有价值的：

- 三个信号定相关度：章节标题/卡片名直接命中最强，正文关键词密集次之，仅术语擦边最弱——擦边命中直接丢弃。
- 最多保留三条，每条`path:line——一句话说明它回答了问题的什么`。
- 拿不准值不值得展开时只给路径与一句话摘要，由调用方决定是否读取——绝不主动贴正文。

## 上下文节约规则

- 先搜索后读片段：grep关键词定位相关小节，再用offset/limit只读命中区间。
- `references/`下的索引文件用于定位而非装载；绝不整读进上下文。
- 在线查询保持窄：一次一个问题，只摘回答问题的关键段落。

## 在线兜底

本地没有时才用：

- Flink 1.19文档——算子语义、状态后端、水位线、SQL
- GitHub上的Velox文档——算子、聚合与标量函数、内存、spilling
- Arrow文档——桥接工作所需的vector布局与互操作细节

优先定向搜索（`site:`限定、精确符号名），不落主页。

## 输出契约

每个回答列明出处：本地命中给`path:line——摘要`，在线命中给URL加回答问题的那一段。找不到就明说，不拿相邻内容改写充数。
